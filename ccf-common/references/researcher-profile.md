# 研究者工作偏好（可选配置）

本文件整理自用户提供的研究习惯建议，供主动采用此流程的研究项目按任务引用。它不是所有安装者自动生效的长期指令，也不是实验成果、权限授予或已验证事实的证明。仅在工作明确涉及本使用者已采用该流程的研究项目（如 SynScale、OrbitFlow）、用户明确采用本画像，或既有项目约定启用本画像时读取相关小节；不要整篇套用到每个任务。

## 适用范围与优先级

- 启用后优先级：当前对话明确指令及已确认的项目协议 > 本画像中的可选工作偏好 > 各 skill 的通用偏好。无论是否启用，本画像都不能覆盖 Humanization → Common 前置、真实证据、隐私与安全规则、`ccfa.yaml` 契约或宿主权限；科学结论始终以检验和实际记录为准。
- 当前指令或实际科学证据与某条习惯冲突时，遵循更高优先级要求；只有偏离影响算力预算、可比性、已冻结协议或交付结论时才需说明，不增加例行过程汇报。
- 启用后需要读取相关小节的工作：研究方向与 idea、实验与算力决定、研究代码与训练、文献筛读、论文或汇报里的结论措辞。排版、引用格式、单段润色和普通绘图不需要读。
- 项目现状（预算余额、当前主线、已过的门）以项目仓库里的记录为准。本画像只写长期习惯，不跟踪进度。

## 研究背景与工作语言

- 可参考的研究背景：异构 LLM 智能体团队的组织、选择与验证（SynScale）；跨领域复用的表示几何内核，包括结构化变换族、可行域、度量和可验证的隐空间适配（OrbitFlow）。具体项目与方法是否适用，以当次任务和项目文件为准；不要将这些例子当成所有安装者的研究方向。
- 讨论、计划、复盘和组会材料用中文，术语保留英文原文（如 advantage、OOD、pass@k、FLOPs）。代码、配置字段和运行记录用英文；论文正文按目标会议的语言写。

## 决策纪律：一次一注，先写好怎么输

“一注”指在**同一受控研究预算中**为决定方向或支撑实证主张而开展的有成本确认性实验。构思阶段的多方向探索、CPU 回放、小规模诊断、文献研究、论文正文与图表增量更新都不算一注，不受其并发限制。仅在用户启用本画像且没有明确授权并行确认性运行时，使用以下默认门禁。

1. 同一受控预算中默认只开一注有成本确认性实验。新想法进入待办，不自动动用当前预算；结清后下一注仍需用户授权。已授权的独立项目、数据分析、写作、绘图或低成本诊断不因此停止。
2. 设计时求“决定性”，不求“最优”。先问哪个结果会改变下一步做什么，再选能区分竞争解释的最小实验，不追求覆盖最全、形式最完美的方案。
3. 对确认性下注，先写预注册卡（模板见下）。首先定义具有科学或工程意义的最小效应与可接受风险，再结合方差、功效、区间宽度和预算确定样本量；不要仅因为统计上能检测更小效应就改变决策界。
4. 先过低成本的 Gate 0：能用现有记录回放、代数推导或 CPU 重算排除无效设计的问题，优先解决。若旧记录**已参与本假设发现、调参或阈值选择**，它们只能提供探索性或反证线索，不能伪装成独立确认；真正确认需要预先锁定协议后的未使用数据。没有参与选择且具有有效预注册身份的数据，依其真实协议判断，不一概排除。
5. 算力分阶段放行。每过一个门才放下一阶段的 CU；门没过就停在当前阶段，不追加预算“再看看”。
6. 触发预注册 kill gate 后按原约定结束该确认性试验，不事后改任务、模型、指标或阈值制造同一试验成功的印象。允许如实补做故障定位、统计勘误和探索性分析；新的确认性设计需重新声明、重新授权，并使用适合的新证据。
7. 已授权的实验线在运行、分析和结论记录闭环之前，不把未完成结果当作终局证据，也不擅自开启新的确认性算力下注。**不阻止**独立的理论工作、文献筛读、现有正文的图位与衔接维护、性能图随有效批次更新，或其他明确授权的文档工作。
8. 新数据优先于重新分析。旧记录的再审计或重算，只在会改变下一次实验设计或某个结论时才做。一批记录用于审计之后，在它上面提出的新问题只能得到描述性证据，检验要换新数据。
9. 每个工作项写明“到什么程度就停”。暂不启动的事项单独列出，只保留接口说明。
10. **性能优越性**主张必须有与其比较口径相称的等预算证据和明确效应。理论性贡献、机制分解、边界条件或负结果不以正向指标提升为先决条件；对弱效应和不确定结果应据实表述，不为了凑改善而调整终点。

预注册卡：

```text
问题（一句话）：
竞争解释，以及能区分它们的观察：
实验臂（参照臂也要重复）：
主终点 / 分析单位 / 判定界或非劣界：
数据：新题来源与种子；哪些记录已经用过（只能作描述性证据）
结局 → 决定：赢 →     输 →     不确定 →
Kill gate：
CU 上限 / 截止日期：
明确不做的事：
```

## 算力与成本口径

- 使用 Colab 时按 compute units（CU）记录预算、上限与实耗；使用 Modal 或其他平台时保留其真实计费单位与转换前提，不能把不同平台成本直接当作同一 CU。估算应包括失败重跑、评估、模型下载和加载等真实开销。
- 验证想法时可优先考虑预算内的小模型，例如 8B 及以下，但不能以固定规模替代任务能力门、实际资源要求或正式对照协议；模型选择以当次项目记录为准。
- 比较应写明对齐预算的口径：调用数、token、近似 FLOPs 或实测 GPU 秒。例如 `2 × 非嵌入参数量 × token 数` 只是一种粗略推理估算，未必覆盖 attention、缓存、批处理或硬件差异，不能冒充精确实测 FLOPs。
- 单次调用成本不能仅按参数规模推算。不同模型、批量、输入长度、缓存和算子实现会改变运行成本；任何特定硬件上的历史倍率都需指向对应运行记录后才能引用，不能当作通用事实。CU/h、吞吐和峰值显存从实际记录读取，不写成固定程序常数。

## 证据与统计口径

在 [research-rigor-gates.md](research-rigor-gates.md) 的基础上，额外遵守：

- 对随机训练干预，推断应覆盖**独立训练运行/种子**及其内部任务的依赖结构：只按题 bootstrap 不能估计训练运行间方差。理想情况下参照臂也要重复；做不到时，明确标注“仅按题重采样，未覆盖训练运行方差”，不把该区间解释为整体训练效应的置信区间。可根据设计采用分层、配对或运行级分析，不能一概断言所有训练比较只有一种推断单位。
- ID 和 OOD 分开报告。差值依赖参照选择时，所有参照下的差值都要报，或者报范围，不把参照选择藏起来。
- 研究学到的子空间、可行域或结构时，若主张超越降维/缩小搜索空间本身的作用，考虑同维数、同覆盖率或相应条件匹配的随机对照，排除低维先验带来的替代解释。
- 对可由完整、可比且授权使用的既有样本进行**离线重放**的投票、验证器选择或路由规则，优先复用记录，避免无谓重跑；涉及交互式条件生成、已变的协议或独立验证时不能将旧样本拼接当作真实新实验。
- 研究干预的效果前，先做任务相关的基础能力检查，避免把模型不具备任务能力与干预无效混为一谈；不要预设某个模型在未检验的具体任务上一定失败。
- 报告中的**实证统计量**应能由原始记录和分析脚本复现；提交前对受影响的数字重算或验证缓存与来源一致。理论常数、文献引用数字及预算计划保留各自来源，不把它们伪装成当前实验测量。
- 引用项目结果前，先找最新的复核记录（如 `BOUNDARY_RECHECK_*`），以复核后的数字为准。区间含 0 就照实写。复核推翻了早先的结论时，写明“更正：旧说法 → 新说法”，并列出受影响的下游表述。

## 选题与理论取向

- 理论先行、跨领域复用。优先寻找在两个以上领域都出现的结构（变换族、约束、度量），做成不依赖深度学习框架的数学内核，再给各领域配薄适配层；不从单一应用的需求倒推理论。这类反复出现的结构，算作 idea optimizer 所说的“尚未解释的现象”。
- 接入新领域时尽可能附带有标准答案或独立验收标准的任务；若内核改动没有宣称改变既有行为，原有基准应通过回归门禁。跨领域共用能力优先进入内核，单领域能力优先放适配层；不能机械要求每个新构件预先得到两个领域采用。
- 不为未来的功能提前增加复杂度，但接口不能把它们堵死。跨项目的连接（例如 SynScale 经 adapter 调用 OrbitFlow）现在只留接口和记录，不提前实现。
- 多智能体组织这类宏观研究，研究对象是边界条件和交互机制。结论写成“在哪些可测的前提下，哪个模块有用或有害”，前提要在搭系统之前就能测出来。产出是开放、可证伪、可扩展的模块，不是封闭的分类法。
- 方向性结论靠“拧旋钮”得到：固定其他参数，只动一个。跨任务的相关性给不出方向，漏掉的变量可能把方向整个翻过来。
- 对旨在跨领域预测的新增参数，优先检查能否事先测量、跨运行是否稳定、能否在未参与发现的领域提升预测力。解释性参数或探索性构件可先保留为假设，不能未验证便提升为普适规律。结构先验是否合理取决于数据、推导或可检验的明确假设。
- 跨学科类比（科学哲学、形式化方法、组织理论、相似律等）可以用，但要落到可检验的预测或可计算的指标上。
- 项目代号可以用文学或历史典故；采用前检查是否与已发表的模型或论文重名。

## 工程习惯

- 在现有代码上小步增量修改。大重构代价太大，只在出现具体的不兼容时才考虑；同时保持开放、可扩展。
- 实验协议与运行配置分开。协议包括数据划分、模型与起始状态、奖励、权重、训练预算和评价终点；运行配置包括设备、精度、attention 实现、TF32、确定性设置、采样引擎、microbatch 和梯度累积。
- 不为适配硬件静默改变有效 batch、生成长度或训练步数。必须改时，记为协议偏离或另一个实验配置。
- “运行配置可切换”不等于“结果可比”。改变卡型、精度或后端时，根据变更风险做数值验收，例如固定批次在不同 microbatch 切分下的梯度**在已声明容差内**一致，以及采样端与训练端 logprob 的偏差和裁剪比例。失败时暂停受影响的比较，不能静默沿用原实验标签。
- 奖励、组内优势之后的加权、表示变换、潜变量更新是不同的干预位置，分别显式实现，不合并成一个万能的 `adapter()`。
- 对确认性、耗费算力或计划发表的运行，保留不可变的 manifest 或现有等价记录，回答：模型状态、数据、操作、产物及训练时可见与仅供评估的信息。记录实际解析的关键环境与硬件信息，标明缺失值；事后补算不能冒充历史观测。一次性轻量调试不强制另建 manifest。
- 表示对象附带规范：kind、producer revision、checkpoint hash、layer/position、shape/dtype/normalization、坐标系。不能因为维度相同、都能存成张量就直接对接；默认用恒等变换，形状不兼容时报错，不悄悄转换。
- 原始记录要比当前理论需要的更全，尤其是信息流向（谁看到了谁的输出），这样以后提出的参数可以在旧数据上回算。
- 复现类工作先做复现准备（版本、数据、checkpoint、许可证、资源测量）和有 CU 上限的可行性测试，不默认启动完整训练。开工前写好复现验收：哪些指标、和论文数字的容差、几个种子。

## 文献与外部来源

- 用户明确要求通读时完整阅读论文；一般问答按所需章节和原文证据深度阅读，并说明它可能影响实验设计、机制假设或论文表述中的哪一项。不能只凭摘要对全文作出确定结论。
- 作者归属、arXiv 编号、研究对象等引用信息都对照原文核实；没有逐条核对的条目要明确标出。
- 不夸大来源：文档“没提到”不等于“说了不需要”。
- 能从表格复算的关键数字就复算，例如均值的口径，以及收益来自完成率还是单题质量；同时检查对方的消融是否对齐算力、有没有报告种子方差。
- 论文原有的内容与我们的推导、解读分开写，后者明确标注。

## 写作、汇报与协作

- 结论强度与证据强度一致：部分支持就写部分支持，探索性图表不升格为结论。
- 组会材料用中文讲稿，术语保留英文；每个数字都对照原文核过，自己补充的推导或示例标注为本人推导。
- 可能被误解的措辞，主动指出并改正。
- 用户给出独立重算的数字时，以原始记录和脚本为准对齐，不为先前的说法辩护。
