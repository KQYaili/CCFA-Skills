## When to lower commitments

Lowering a commitment is not deleting content; it is calibrating the
promise level to the evidence strength. Trigger it when:

- the proposal is written inside an already-funded programme's frame
  and the draft states exploration directions as core deliverables;
- a fundamental theoretical, engineering, or ethical constraint means
  the planned route cannot carry a high-strength promise;
- a Gate-2 content review returns a P0 finding about promise level;
- the evidence table shows the flagship claim resting on literature
  analogy rather than on the team's own preliminary results.

## The three commitment tiers

| Tier | Definition | Wording |
| --- | --- | --- |
| Deliverable main line | Literature support + the team's conditions are in place; must be achieved | "establish …", "determine …" |
| Cautious exploration | Literature leads exist but transfer risk to this system is high; attempt, no guarantee | "explore the feasibility of …", "test whether … holds" |
| Boundary confirmation | Only answers "can this be done at all"; no optimization promised | "determine the operating window and the Go/No-Go criteria for …" |

## Procedure

1. List every claim in the draft; tag each with a tier.
2. Shrink the main line: only deliverable-tier claims stay as core
   outputs.
3. Demote over-promised "core innovations" to cautious exploration,
   each with an explicit failure criterion and a fallback route.
4. Make boundaries explicit: write "if X proves infeasible → fall
   back to route Y" in the text, not only in the work notes.
5. Rewrite the positioning sentences of the whole proposal so the
   summary reflects the demoted commitment structure.

## Stop rules

Stop iterating — and report instead of polishing — when any holds:

- 3 revision rounds have run;
- two consecutive rounds each improved the score by less than 0.5;
- evidence needed for a key claim is missing;
- an expert conflict cannot be honestly resolved;
- the user's target for the current deliverable is reached.

On stopping, report: current score/status, remaining problems, why
the loop stopped, and one recommended next action. Never hide an
unresolved evidence gap under smoother prose.
